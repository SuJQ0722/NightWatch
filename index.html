TL;DR

Computer-use agents look at the screen on their own clock: take a screenshot, reason, act, sleep for a fixed delay, repeat. On a live screen this goes wrong both ways. The agent reasons about a screen that has already changed, and it sleeps through a page that loaded long ago. NightWatch lets the screen decide when the agent looks. A 0.8B watcher reads the screen as a stream and, through three fixed rules, interrupts reasoning that a change has made obsolete, voids a click whose target is gone, and wakes the agent the moment the screen settles. The agent itself is not modified.

Three proactive interventions

Interrupt

during reasoning

A dialog, an error or a new page appears while the agent is still reasoning about the old screen. NightWatch cancels the generation, and the agent re-plans on the current screen.

Void

before dispatch

The element the agent chose to click has moved, been covered, or disappeared. NightWatch discards the action before it lands, instead of letting it hit the wrong target.

Wake

after execution

The fixed sleep after each action is replaced: NightWatch wakes the agent as soon as the screen has settled, learned from hindsight labels rather than from stillness alone.

Demos

Each video shows four real episodes side by side, with the same agent (MiMo-V2.6-Flash), prompt, action space and step budget. Each panel shows the agent's state and its intervention log, with a timeline coloured by what the loop was doing. Playback slows to 1× around NightWatch's interventions. The closing card reports the episode times and each method's success over the three paper runs of that task.

Interrupt: the screen changed while the agent was reasoning

OSWorld-Verified · “Run ls in /home/user and save a screenshot of the terminal as ls.png on the Desktop.”

The Files window finished opening while the agent was still reasoning about the half-drawn screen. NightWatch cancelled that reasoning, and the agent re-planned on the current screen and finished in 7 steps. Over the three paper runs: NightWatch 3/3, Vanilla 1/3, AOI 0/3, PUSV 1/3.

Paper runs, run 2 of 3. Screenshot replay: each frame is a screenshot the agent received, shown at its logged time (OSWorld runs were not screen-recorded).

Void: the swatch moved before the click landed

DynaCU-Bench · “Click the matching color swatch when it appears among rotating options.”

The swatches rotate while the agent reasons. Twice, the swatch the agent chose had already moved when the click was due: NightWatch voided the click instead of hitting the wrong colour, and the agent re-planned on the current screen. Over the three paper runs: NightWatch 3/3, Vanilla 3/3, AOI 2/3, PUSV 2/3.

Continuous screen recordings. NightWatch: paper configuration, episode chosen to show the intervention; baselines: the first demo recording of each method.

Interrupt: a server went critical mid-thought

DynaCU-Bench · “Three servers will go critical at different times. Acknowledge each within 5 seconds of it going red.”

When the next server turned red while the agent was still reasoning about the old screen, NightWatch cancelled that reasoning at once, so the agent saw the new alarm in time. Over the three paper runs of this task: NightWatch 3/3, Vanilla 2/3, AOI 1/3, PUSV 1/3.

Continuous screen recordings from one demo session with the paper configuration; the first recording of each method.

Wake: look as soon as the page has loaded

OSWorld-Verified · “Browse list of Civil Division forms.”

All four agents solve this run. The agent writes sleeps into its own actions while pages load; NightWatch strips them and wakes the agent as soon as the screen settles. Outside reasoning, a step costs 4.1 s with NightWatch against 15.1 s (Vanilla), 9.4 s (AOI) and 14.3 s (PUSV); NightWatch finishes in 193 s.
